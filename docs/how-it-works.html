What it is

A team of specialists, not one prompt

Solving CTF challenges spans wildly different skills — breaking RSA, decompiling a binary, carving a disk image, probing a web app. A single agent carrying every tool and every instruction does none of them well. This system splits the work: a lightweight recon pass gathers facts, an orchestrator routes to the right specialist, and a deterministic verifier decides when the flag is actually found. Each specialist runs in an isolated sandbox with only the tools its category needs.

The design follows a finding from the research literature (EnIGMA, D-CIPHER): for CTF agents, the tool interface matters more than a clever agent loop. So the effort goes into clean tool access and honest measurement, not orchestration theatre.

Recon deterministic

Runs ls, file, strings up front. No LLM. Sharpens routing and briefs the specialist so it starts informed.

Orchestrator

Picks the specialist from the challenge category (or recon's guess), then hands off with a ready-made brief.

Specialist

Category-tuned prompt + a scoped tool set, driving a shell inside the sandbox.

Verifier deterministic

Regex-matches the flag format. The moment a flag appears in any output, the loop stops — no wasted turns.

Sandbox — Docker

One Kali container per challenge, task files mounted read-scoped. Real isolation for untrusted binaries. Kali base + Rosetta runs x86-64 on Apple Silicon.

Sandbox — local

Host shell in the challenge dir. No isolation — trusted crypto/general only; needs no container, useful for fast iteration.

Audit log

Every command, its output, and the agent's reasoning, timestamped. Deterministic ground truth — no model touches it.

Writeup

One LLM pass narrates the audit log into a human CTF writeup. It can't invent steps that aren't in the trace.

Pipeline

Five steps, per challenge

  1. Recon.

    Deterministic probes (ls · file · strings) build a brief and a category guess. Cheap, reliable, and it stops the specialist from rediscovering the filesystem.

  2. Route.

    The orchestrator maps the challenge category (from the benchmark label or recon) to one of six specialists.

  3. Solve.

    The specialist drives sandbox_bash — an MCP tool wired to the container — inspecting, hypothesising, and testing with its category's tools.

  4. Verify & stop.

    Every command output is scanned for the flag format. First match auto-terminates the loop — the key cost control.

  5. Record.

    The run emits audit.jsonl (ground truth) and writeup.md (narrated). Scoring is strict, with a separate near-miss column for cracked-but-mis-formatted flags.

Results · InterCode-CTF (picoCTF-based)

Measured, and honestly

One iteration, measured. The auto-terminator was firing on encoded flag look-alikes — a ROT13'd cvpbPGS{…} matched the loose flag regex and stopped the solver before it decoded. Pinning the pattern to picoCTF{…} recovered four crypto solves. Find the failure mode, fix it, re-measure the gain.

Where it still fails

  • Dead remote servers. The Web tasks point at live picoCTF hosts (now decommissioned) with no local files, so they're unsolvable offline — a dataset limit, not a solver gap. The real-world platform targets live authorised hosts instead.
  • Remote-service pwn. Some pwn challenges need a running service; local-only ones (source provided) fare better.
  • Case near-miss. Cracked, wrong case. Content case is genuinely unknowable to the solver, so it's reported, not chased.

A balanced 6-category run (38 tasks, full toolset, retries) scored 27/38 (71%) — 75% once the dead-server Web tasks are excluded — in 1164s at concurrency 5.

Usage

Running it

Setup

# python venv + the Claude Agent SDK (needs the `claude` CLI on PATH)
python3 -m venv .venv && ./.venv/bin/pip install -r requirements.txt

Import a benchmark

# 100 InterCode-CTF tasks; gold flags kept OUT of the sandbox
python import_intercode.py path/to/intercode/data/ctf -o challenges/intercode

Run — local backend (crypto / general, no container)

CTF_SANDBOX=local ./.venv/bin/python run.py challenges/intercode \
    --category crypto --max-turns 20

Run — Docker backend (forensics / rev / everything)

docker build -t ctf-agent:latest -f Dockerfile.lean .
./.venv/bin/python run.py challenges/intercode --per-category 5 --max-turns 15

Each solve writes audit.jsonl and writeup.md into the challenge folder; the runner prints a live solve rate and per-category breakdown.

Scope

Built vs. deferred

● Working now

Orchestrator, recon, verifier, both sandboxes, audit + writeup, crash-safe batch runner, near-miss scoring, InterCode import.

● Tools wired

Crypto (pycryptodome, sympy, z3, RsaCtfTool), forensics (binwalk, exiftool, zsteg, steghide, tshark, foremost), rev (radare2, gdb).

● Deferred by design

Stateful MCP tools — GhidraMCP (rev), pwndbg-mcp (pwn), Playwright (web) — added when a batch shows they're needed.

● Known limits

SageMath (heavy) and pwntools/unicorn (cmake) live in the full image, not the lean one; content-case near-misses left honest.
